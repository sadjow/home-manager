# Harness Evolution Specialist Contract

Use a harness-evolution specialist for a bounded audit, design, refactor, or independent review that spans several harness layers. Do not require it for an ordinary correction that the current agent can promote safely with the main skill.

## Activate when

- always-loaded guidance is growing or duplicated across products
- instructions, skills, agents, checks, hooks, and CI need coordinated ownership changes
- a broad pruning or migration needs an independent preservation audit
- product adapters disagree or a capability route is not being used reliably
- parallel read-only investigation would materially reduce elapsed time or context mixing

## Do not activate when

- the work is a one-line instruction correction
- a deterministic script, test, formatter, or link check can answer the question
- the task is tightly sequential and delegation would require copying the same large context
- the user disallows delegation or a human authority decision is still required

## Evidence packet

Give the specialist only what it needs:

- requested operating mode and allowed mutations
- canonical personal and project ownership boundaries
- concrete incident, correction, or measured context problem
- relevant entrypoints, capability metadata, and adapter paths
- known validation commands and unrelated work that must be preserved

Do not forward full conversation history when a concise evidence packet is sufficient.

## Operating contract

The specialist must use the `evolve-agent-harness` and `improve-project-harness` workflows rather than restating them. It should:

1. distinguish immediate repair from reusable promotion
2. identify the smallest reliable control and canonical owner
3. keep portable capability logic agent-neutral and product adapters thin
4. preserve full-fidelity project learning without leaking it into personal scope
5. avoid reviewer swarms and recursive delegation
6. protect existing outcomes before pruning or moving guidance
7. validate discovery, original, transfer, boundary, and conflict cases where practical

The coordinator remains responsible for integration, final validation, and user communication.

## Expected output

Return a concise packet containing:

- evidence and root decision failure
- proposed ownership and context layer
- control surface and adapter plan
- material risks and preserved behavior
- validation evidence or the exact remaining validation gap
- whether edits were made and which files are owned by the specialist

## Product adapters

Use a native custom-agent definition only when the product supports and discovers it reliably. Otherwise, the coordinator may delegate the same bounded contract to a generic worker or reviewer. The portable skill remains the source of workflow truth; product-specific agent prompts contain only discovery metadata and the minimal adapter behavior.
