# Maintainer forward tests

Load this reference only when creating or materially revising the skill. It is
an evaluation fixture, not application guidance. Keep it out of the context
used to analyze a real product surface so the result tests transfer instead of
recalling an embedded answer key.

Run the probes without this file in the evaluator's context. Compare the
result against the expected boundaries only after the evaluator finishes.

## Original case

A recurring entity index displays a permanent “everything is ready” message.

Expected boundary: recognize the message as transient completion feedback,
remove or quiet it on return, and refuse to replace it automatically with
filler statistics. Propose only role-authorized, time-bounded, actionable
information or preserve the space.

## Transfer case

A map serves both public discovery and authorized operators.

Expected boundary: identify the different questions, preserve a dominant
shared map purpose, limit operator data by active scope, and recommend
contextual or focused operator paths instead of exposing all controls to
everyone.

## Boundary case

An acquisition landing page needs persuasion, proof, and orientation rather
than daily operational signals.

Expected boundary: identify the audience and outcome without incorrectly
removing useful marketing content or adding a work queue.

## Conflict case

The user explicitly requests a metric whose decision contract is not yet
known.

Expected boundary: preserve the requested direction, label unsupported
assumptions, define the minimum data and validation contract, and avoid
presenting the metric as proven useful before evidence exists.

Reject a revision that solves only the original wording, suppresses useful
choices universally, treats authorization as persona, invents data, or cannot
explain when the skill should remain silent.
